Problem statement

Knowledge is scattered. Failure is repetitive. Both cost the same thing — time.

Coles IT Operations runs a national estate: stores, checkouts, EFTPOS, refrigeration, distribution centres and the platforms behind them. Two structural problems drive most of the avoidable effort.

Answers live in people, not systems

Runbooks, SOPs, the known-error database and past RCAs sit in different repositories with different owners. The fastest path to an answer is asking whoever handled it last time.

Knowledge decays silently

Nobody is measurably accountable for staleness, duplication or contradiction. A runbook can be wrong for months before anyone notices — usually mid-incident.

Every incident is solved from scratch

Resolved incidents rarely become reusable articles. The same EFTPOS terminal fault gets re-diagnosed at a fourth store because the first three fixes were never written down.

Operations is reactive by design

Monitoring tells you a threshold has already been breached. Recurrence, seasonality and slow degradation are visible in the data but nobody has time to look for them.

Signals never meet each other

Ticket trends sit in one platform, telemetry in another, change records in a third. The correlation that explains a problem is real — it's just never assembled.

And the obvious fix is the dangerous one

A chatbot over the wiki produces confident, unsourced, occasionally wrong answers — and puts customer and team-member data in front of a model. That failure mode is worse than the problem.

The hard requirement isn't "add AI to IT Ops". It's: never answer without evidence, never expose raw PII to a model, and let nothing change a live system without a guard in front of it. Every design decision below follows from those three.

The solution

Seven agents, one governed platform

Every agent runs on Microsoft AI Foundry behind a single API Management gateway, authenticates with its own Entra Agent ID, and reaches knowledge through the same grounding plane. They reason; they never execute. Everything they say is traceable back to a document, a model run or a change record.

The six principles everything is built on

Enforced in infrastructure — not in prompts. A prompt can be argued with; a policy cannot.

P1

Agents reason; tools execute

Agents emit intent. A tool proxy carries it out, with idempotency keys, approvals and rollback — and it is the only layer that resolves a pseudonym back to a real identifier. DC Ops is the single agent holding write authority, behind a change-window guard and automatic post-apply rollback.

P2

No raw PII reaches a model

A mandatory de-identification tier pseudonymises every inbound request with stable reversible tokens. The token vault is unreachable by the agent's own identity; re-identification happens at render time, for entitled users only.

P3

No answer without evidence

A paired critic checks every claim against a retrieved chunk. Ungrounded output is blocked and handed to a human — never surfaced with a caveat.

P4

Every action attributable

One correlation ID spans channel → gateway → workflow → agent → tool → ITSM. Signed, immutable run records land in ADLS under legal hold.

P5

Autonomy is earned

Advisory → suggest → approve-and-execute → auto-execute, configured per action type and promoted only on measured evaluation evidence.

P6

Stateless agents, stateful workflows

Long-running work — weekly watchlist runs, curation sweeps — lives in Durable Functions, not in the agent's head.

Data flow · architecture layers

How a question becomes a grounded answer

Every call — from a human, a dashboard or another agent — takes the same path through the same seven layers. There are no point-to-point integrations.

Caller → Front Door + WAF → App Gateway → APIM AI Gateway → De-identification → Foundry Agent → Tools & grounding → Critic → Signed run record
Layer 1Consumers
Agent AssistVoice Agent Conversational AgentRCA Agent DC Ops AgentOps dashboards / Teams Engineers & knowledge owners

Every call carries an Entra Agent ID token (on-behalf-of for user-initiated requests), an APIM subscription key, a correlation ID and the calling agent's name.

Layer 2Ingress rail
Front Door Premium + WAF App Gateway WAF v2APIM Premium v2 · AI Gateway token limitssemantic cache Prompt Shieldscircuit breaker

OWASP rules, bot protection and AU geo-fencing at the edge; per-consumer token quotas, Redis semantic cache and content-safety prompt shielding at the gateway. APIM authenticates to Foundry with a managed identity — no model keys ever sit in application code.

Layer 3De-identification tier
Azure AI Language PII detect Coles custom recognisersstable pseudonyms Cosmos token vault (CMK)render-time re-identification

Mandatory, and it sits between every channel and every model call. Employee number, store number, team-member ID and loyalty ID are detected by custom recognisers, then replaced with stable reversible tokens (PERSON_1, EMP_0042) rather than masked — masking would destroy the coreference the model needs. Redaction fires at confidence ≥ 0.5 and fails closed.

Layer 4Agent plane
Foundry prompt agents hosted container agents Durable Functions orchestrationMCP Toolbox model router (mini / reasoning)

Stateless, session-isolated, managed-identity agents that see pseudonyms only. Long-running flows are orchestrated outside the agent so a restart never loses a workflow.

Layer 5Grounding & data
Foundry IQ Azure AI Search — hybrid BM25 + vectorsemantic ranker Document IntelligenceADLS Gen2 Cosmos DBFabric OneLake Managed Redis

One index per corpus — runbooks, SOPs, KEDB, RCA library, CMDB descriptions — each security-trimmed by Entra group so retrieval never exceeds the caller's own entitlements. Content is PII-redacted at index time: a successful prompt injection cannot exfiltrate what was never indexed.

Layer 6Classical analytics plane
Azure ML forecasting (versioned) Azure ML anomaly detectionFabric analytics Event Hubs telemetrydeterministic risk scorer

Predictive-only. This is where the maths happens, and it is auditable and reproducible: every projection carries its model version and run ID. Risk scores are computed by a deterministic function, not by a language model.

Layer 7Trust rail (cross-cutting)
Entra Agent IDPurview DSPM for AI Content Safety + Prompt Shieldsgroundedness critics App Insights + OTelimmutable run records VNet + Private Endpoints

Applies to every call in every layer. Each agent is a first-class security principal with its own RBAC and Conditional Access, and every output is a signed record you can replay months later.

Sync

Request path

REST through APIM. Under load, knowledge queries degrade to retrieval-only rather than failing outright.

Async

Event path

Service Bus topics knowledge.ingest and predictive.risk-alerts; Event Grid for doc, ITSM and monitor events; Event Hubs streams telemetry to Predictive.

Resilience

Active-active

Australia East / Southeast, Cosmos multi-region write, AI Search replicas ≥ 3. RPO 15 min, RTO 1 h for agent state — the index itself is rebuildable from source of truth.

The seven agents

What each one does

They aren't seven peers doing the same job — they sit in tiers, and the escalation path between them is the product. Knowledge owns the index and grounds everyone above it; nobody else has one.

Front line Conversational · Voice

Same capability, different channel — chat and portal versus phone and Teams. They answer what they can and raise a clean ticket when they can't. Neither escalates to a specialist directly.

→
Triage Agent Assist

The L1 co-pilot. Gathers catalogue context, runbooks and similar incidents, ranks remediations, then routes on incident type — deterministically, from data it already holds.

→
Specialists RCA · DC Ops

Infrastructure goes to DC Ops, code defects to RCA. RCA publishes its approved analysis back into Knowledge, so the whole fleet gets smarter from one incident.

Cross-cutting Knowledge · Predictive

Underneath all three tiers. Knowledge grounds every agent above it. Predictive reads the whole ticket estate rather than any single incident, pushing recurrence, forecasts and the weekly watchlist to Agent Assist and DC Ops.

Agent 01Triage Phase 1

Agent Assist

The L1 co-pilot beside the ticket. Resolves what it can, routes what it cannot.

RoleParses the incident, then fans out in parallel to the service catalogue, the runbooks and similar past incidents before ranking remediations.
HowRoutes deterministically on CI class — infrastructure to DC Ops, code defects to RCA, store hardware and identity requests stay here.
GuardrailA groundedness critic sits between remediation and routing, so no suggestion reaches an engineer under time pressure without a runbook behind it.
AutonomySuggest only. It pre-fills the brief and the structured handover; the engineer decides and the engineer acts.
MetricRemediation acceptance rate — how often the engineer follows the top-ranked suggestion.
Agent 02Front line Phase 2

Conversational Agent

Self-service in Teams and the portal, for the questions that never needed a ticket.

RoleClassifies intent with a cheap mini-tier model, then answers from grounded knowledge or collects a well-formed ticket across several turns.
HowSession state lives in Cosmos, so the graph can end a turn and wait when required fields are still missing.
GuardrailA fallback branch catches low-confidence classification and a warm-transfer path carries the full context to a human, rather than dead-ending.
AutonomyAdvisory. It answers and can open a ticket through a tool proxy; it changes nothing else.
MetricContainment against handover — resolved without a human, versus escalated.
Agent 03Specialist Phase 3

RCA Agent

Post-incident analysis whose output becomes everyone else’s grounding data.

RoleBuilds a unified timeline from telemetry, alerts and change records, adds prior cases and public vendor context, then generates hypotheses.
HowOn approval it publishes to Service Bus knowledge.ingest, so the RCA is indexed and every other agent gets smarter at once.
GuardrailAn evidence critic strips any claim not bound to a timeline entry, a source or a change record before a human reviews it.
AutonomyDraft only. Nothing is published and no article is created without a named human signing it off.
MetricRepeat-incident rate — whether RCAs are actually preventing recurrence.
Agent 04Cross-cutting Phase 1–2

Knowledge Agent

The grounding hub. It owns the index; the other six agents call it.

RoleDecomposes the question, retrieves across runbooks, SOPs, the KEDB and the RCA library, reranks, then synthesises an answer bound to citations.
HowOne index per corpus, hybrid keyword and vector, security-trimmed by Entra group so retrieval never exceeds the caller’s own entitlements.
GuardrailThe groundedness critic blocks rather than caveats — unsourced output returns NOT_GROUNDED with a structured handover, never a hedged answer.
AutonomyAdvisory to serve, draft-only to curate. New articles land as pull requests; a knowledge owner publishes them.
MetricGroundedness pass rate, and the gap backlog every block creates.
Agent 05Cross-cutting Phase 2

Predictive Agent

A weekly risk watchlist across the whole estate, not any single incident.

RoleReads ticket history, long-range metrics and change records, then runs versioned Azure ML forecasting and anomaly models over the window.
HowThe risk scorer is a deterministic function — likelihood times business impact, ranked. The model writes the explanation, never the number.
GuardrailAn evidence critic requires every sentence to bind to a classical-model output or a change record; unsupported claims are stripped out.
AutonomyAdvisory only. Its Entra scope has no write access beyond its own container and its own topic.
MetricPrediction accuracy — the only evidence that unlocks more autonomy.
Agent 06Specialist Phase 3

DC Ops Agent

Network and database operations — and the only agent that writes to production.

RoleReads Network Watcher alerts and SQL tuning recommendations, decides on a query-plan rollback, then grounds each alert category in a runbook.
HowIt applies that rollback against Azure SQL directly. Every apply emits an immutable change record carrying the triggering alert’s correlation ID.
GuardrailA change-window and approval guard runs before the apply; post-apply verification rolls back automatically if the metric has not recovered.
AutonomyWrite authority, guarded — the only such scope in the fleet. Publishing to the knowledge base still needs a human.
MetricPost-apply verification success, and the rollback history it leaves behind.
Agent 07Front line Phase 2

Voice Agent

The same reasoning stack behind a phone line, with the PII boundary intact.

RoleSpeech to text, then intent, slots, policy check and action — reasoning on pseudonyms only, exactly like every other agent here.
HowBuilt as a discrete pipeline rather than speech-to-speech, because an integrated path leaves no text checkpoint at which to pseudonymise.
GuardrailIdentity is a deterministic Entra check, never a model decision, and every auto-execute action is read back and verbally confirmed first.
AutonomyAuto-executes a closed set — password and PIN resets, logging an incident. Access requests always route to an approver.
MetricContained calls, and confirmation captured on every executed action.

Worked example — all the way through

EFTPOS terminal offline, store 0417

A store rings the Voice Agent. Identity is verified deterministically against Entra before any model turn; the intent classifies as an incident, which is on the auto-execute list, so INC-2026-08872 is logged. Agent Assist opens the ticket for the engineer with the answer already there — grounded in SOP-EFTPOS-TERM-FAULT-001, with section, version, last-updated date and the prior incident it was derived from. Meanwhile the Predictive Agent has already raised RSK-2026-0713: "store 0417 EFTPOS recurrence — 4th occurrence this quarter", evidenced by three incident IDs, with the same SOP cross-referenced and a recommendation to check the terminal firmware baseline. The RCA Agent assembles the analysis; once a human approves it, it publishes to knowledge.ingest and becomes a new KB article. The fifth store never has this problem. At no point did an agent change a live system on its own.

Delivery roadmap

Three phases, and autonomy earned at each one

The seven-agent programme lands in three phases. Scope widens only when the previous phase has the evaluation evidence to justify it.

PHASE 01

Ground truth

Establish the platform and make knowledge trustworthy.

Knowledge — serveAgent Assist
  • Platform rail: Front Door → App Gateway → APIM AI Gateway, Entra Agent ID, VNet + Private Endpoints
  • De-identification tier and token vault live before any model call
  • Knowledge Agent serve loop: grounded Q&A with citations, groundedness critic blocking
  • Agent Assist consuming POST /query beside the ticket
  • Corpora indexed and security-trimmed: runbooks, SOPs, KEDB
PHASE 02

Foresight & reach

See problems earlier; meet people where they already are.

PredictiveKnowledge — curateVoiceConversational
  • Predictive Agent: classical forecasting and anomaly models, deterministic risk scorer, weekly watchlist
  • Knowledge curate loop: freshness, duplicate/conflict and gap detection; article drafting as draft PRs
  • Voice Agent on the closed-set action policy — deterministic identity verification first
  • Conversational Agent for self-service deflection on the same grounded route
  • Feedback loop closed — prediction accuracy becomes a reported KPI
PHASE 03

Compounding & autonomy

Knowledge that grows itself; execution that has earned the right.

RCADC OpsAction API
  • RCA Agent publishing approved analyses to knowledge.ingest — incidents become articles
  • DC Ops Agent using forecasts for capacity and confirming prediction outcomes
  • Action API layer: idempotency keys, approvals, rollback
  • Selected action types promoted to approve-and-execute on eval evidence (P5)
  • Active-active AU East / AU Southeast at full production posture
1 · AdvisoryWhere most agents sit today — recommend only
2 · SuggestPre-filled actions a human confirms
3 · Approve & executeAgent acts after explicit approval
4 · Auto-executeNarrow, well-evidenced action types only

Autonomy is configured per action type, never per agent. The Voice Agent already auto-executes three specific low-risk actions while staying advisory for everything else — that is the model, and every promotion has to be justified by measured evaluation results.

Benefits

What Coles gets out of it

Some of this is speed. Most of it is that the organisation stops paying the same cost twice.

01

Faster, consistent resolution

The same grounded answer reaches every channel — assist, voice, self-service — instead of depending on who happens to be on shift.

02

Knowledge that maintains itself

Staleness, duplicates and contradictions are surfaced continuously rather than discovered mid-incident. Gaps become a prioritised backlog instead of tribal folklore.

03

Incidents compound into assets

An approved RCA becomes a drafted KB article automatically. The fourth store with the same EFTPOS fault gets the first store's fix.

04

Reactive becomes pre-emptive

Recurrence, capacity breach dates and slow degradation are flagged with an evidence trail and a recommendation, days before a threshold trips.

05

Routine work leaves the queue

Password and PIN resets resolve on the phone in a couple of minutes, verified against Entra — while access requests still get the human approval they require.

06

Auditable by construction

One correlation ID and a signed, immutable run record per output — inputs, chunk versions, model and prompt version, tool calls, critic verdict, human decision, outcome.

07

Privacy risk removed, not managed

The model never sees raw PII, and index-time redaction means even a successful prompt injection has nothing to exfiltrate.

08

Hallucination is a blocked state

Ungrounded output is a handled error path, not a customer-facing surprise. That is what makes the programme deployable in a regulated retail environment.

09

One platform, seven agents

Shared gateway, shared identity, shared grounding plane. Every additional agent is cheaper than the one before it — no point-to-point integrations to unpick.

10

Autonomy without a leap of faith

Nothing gets more authority because it feels reliable. It gets more authority because the accuracy numbers say so, per action type, reversibly.
